# FigSmith · 通用方法论（core/METHOD.md）

> 本文件是全项目唯一的方法论来源。域包 SKILL.md 只做本域的补充，**不得与本文件冲突**。
> 一切结论都可用脚本复核，不靠「感觉」。

---

## 0. 一句话

**专业感九成来自一致与对齐，不靠美术。**

---

## 1. 基础八原则

| # | 原则 | 落地做法 |
|---|---|---|
| 1 | **四层分离** | 内容(文字) / 拓扑(谁连谁) / 布局(坐标) / 样式(色字体线宽) 各自声明，互不混写。四层在 IR 里是四个独立字段。 |
| 2 | **语义色板** | 颜色一律 `core/tokens` 查语义常量，代码里不出现 hex。强调色全文 ≤3 种。 |
| 3 | **图元 ≤5 个** | `box` / `arrow` / `polyline` / `band` / `label`。复杂图全靠组合，不加新图元。 |
| 4 | **无量纲坐标系** | 抽象单位（默认 0~100）内设计；画布/dpi/物理尺寸交给渲染器。 |
| 5 | **网格节奏** | 等距列、统一框尺寸、统一行距、公共中轴。全部从 tokens 的 `grid.*` 取，不手填。 |
| 6 | **重复结构循环化** | 加一个节点 = 加一行数据，不手改坐标。 |
| 7 | **克制** | 细线 0.8–1.7；箭头用灰不用黑；无阴影、无渐变、无 3D；留白充分。 |
| 8 | **源与产物分离** | 脚本/配置是源，SVG/PNG/PDF 只是产物。源在，图永远能再生。 |

## 2. 布局类补充（九条）

1. **文字宽度预算** —— `CJK 字数×1.0×字号 + latin 字数×0.55×字号`（`tokens.text_width()` 已实现）。
   终点距容器边留 ≥10px。**超了拆行，不缩字号。**
2. **附属元素贴近主体** —— 图例/脚注距主体 ≈ 一个箭头长度（40–60px）。间距过大视觉上等于「断联」。
3. **画布随内容收紧** —— 画布 = 内容 + 对称边距（各约 40px）。不留无意义白边。
4. **骑缝标题牌有碰撞区** —— 白底色字牌外扩矩形（`band_y±16`）成为新禁行区；带内右上角标基线
   `band_y+26`；横向连线走 `band_y+40` 以下。
5. **标签白描边** —— 跨区标签一律 `paint-order="stroke"` 白描边 4.5px，压线仍可读。
6. **同轴对齐优先于美观** —— 能共中轴就共中轴；对齐关系可比「看起来舒服」更能暴露位移缺陷。
7. **留白是结构的一部分** —— 空白处不许塞装饰。宁可空，不要满。
8. **数值一律来自数据，不来自目测** —— 位置、间距、字号全部可由脚本反算出来。
9. **先定边界再画内容** —— 画布尺寸和边距先算出来，内容往里填；不要画完再裁。

## 3. 统计图补充

- 原始数据、统计定义、单位**优先于**风格迁移。数据没冻结，不动笔。
- CI/SD/SE 分开声明；分类图记录类别、阈值约定、评价集。
- **绝不手挪数据点。** 不为美观改数据。要改数据先改数据源，再重新生成。
- 坐标轴必须标注单位；无量纲的显式写 `a.u.`。
- 图例能省则省 —— 直接标注在数据旁通常更清晰。

## 4. 四条生成路线

按**图的性质**分，不是一路 SVG 到底。

| 图性质 | 前端 | 为什么 |
|---|---|---|
| 结构化图（框/线/箭头） | 裸写 SVG + `<style>` 块 | 完全可控、矢量、可编辑 |
| 统计/数据图 | matplotlib，JSON spec 驱动 | 数据不能手画，点必须来自冻结表 |
| 布局类（海报/幻灯片/信息图） | HTML/CSS → 矢量导出 | CSS 布局强于手算坐标；文字流式排版是 SVG 弱项 |
| 互操作（已有 mermaid/drawio） | 解析成 IR → 按本体系重渲染 | 不透传，否则风格体系崩坏 |

## 5. 从 figcraft 继承的硬坑（必须规避）

| 坑 | 后果 | 规避 |
|---|---|---|
| SVG `<style>` 覆盖 presentation attribute | `text{fill}` 让彩色标题渲染成近黑 | `fill` 不写进 CSS，颜色从包裹 `<g fill>` 继承，逐元素设 |
| 用 `<img src="*.svg">` 导出 | 斜体泄漏、层叠异常 | 只用 inline HTML 通道 |
| `fullPage: true` 截图超一屏页面 | 静默拼接成 4 份重复内容 | 先 `evaluate` 量 `scrollWidth/Height` → 视口精确对齐（≤3840×2160）→ 普通截图 → `check_tiling.py` 复验 |
| tspan 继承斜体 | 数学下标被斜体化 | 下标显式 `font-style="normal"` |
| 每次 JS 调用是新 kernel | 复用旧 handle 报错 | 重新 bootstrap，按已验证 id 绑定 tab |
| 修完不重建导出页 | 旧版本烤进页面 | 改完必须重建 inline export page |
| 发丝线对比度损失 | 1.2px 线理论对比丢 60%，Δ50 渲成 Δ12，judge 读成「无边框」 | 按**实际渲染像素**选色，要求灰度差 ≥40 |

## 6. 验收闭环（全项目命门）

```
几何自检 → 数据一致性 → [交付物回渲] → 视觉裁判 → 按像素证据修根因 → 定向复检
  纯脚本      域相关       PDF/PPTX→位图   原生 read   人工/Agent    只查 FAIL 项
```

### 6.1 三类检查，缺一不可

1. **几何自检**（纯脚本，无需视觉）
   - `core/verify/check_tiling.py` —— 截图平铺检测（文件大小抓不到）
   - `core/verify/check_overflow.py` —— 溢出 / 重叠 / 文字宽度预算
   - `core/verify/check_contrast.py` —— 正文与网格线灰度差 ≥40，在**实际渲染像素**上量
2. **数据一致性**（域相关）—— 数值 / 单位 / 样本量 / 显著性 vs 源数据。绝不手挪数据点。
3. **视觉裁判**（原生 `read` 工具）—— 派发格式见 `core/verify/judge_template.md`。

### 6.2 铁律

- **不伪造 PASS。** 没有视觉工具就明确标「视觉验收待完成」，不许写 PASS。
- **按像素证据修根因，不做局部补丁。**
  已知真实案例：标题变黑 → 根因是 CSS `text{fill}` 覆盖了 SVG presentation attribute。
  已知真实案例：框偏 33px → 真实位置从对齐关系反推出来，不是目测挪回去。
- **定向复检**：只查上一轮 FAIL + 回归点，不重跑全量。
- **批量**：每 judge 3–4 张图，多 judge 并行。

## 8. 技术约束

- Python 3.10+；numpy / matplotlib / Pillow。
- 输出后端优先纯 Python（不强制 headless 浏览器）；HTML/CSS 路线可选 Chromium。
- **不依赖联网字体。** 离线模式必须可用；字体缺省时按 tokens 的 `*_fallback` 降级。
- 印刷域默认 600dpi；屏幕域 96dpi；位图不低于 144dpi。
