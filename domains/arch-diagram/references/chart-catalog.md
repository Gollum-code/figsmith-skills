# arch-diagram · 图型目录

> 选型看「要强调什么关系」。

---

## 1. layered · 分层架构

**强调**：系统分几层，每层干什么。

```
IR 关键点：
  topology.nodes 里每个 band 一个 kind:"band"，每层组件若干 kind:"box"
  band 的 row_span 覆盖整行，box 落在 band 之内
  edges 只画跨层调用，层内不画
```

常见层数：3 层（表现/业务/数据）、4 层（接入/网关/服务/存储）。
超过 6 层 → 拆图。

## 2. pipeline · 数据流水线

**强调**：数据从哪来到哪去，经过几步。

```
IR 关键点：
  单排等宽 box，箭头等长
  label 写在箭头上方（acquisition / filtering / selection）
```

## 3. state_machine · 状态机

**强调**：有哪些状态，什么条件触发转换。

```
IR 关键点：
  圆角框（radius.badge），状态名居中
  edges 带条件标签：{from, to, label: "条件"}
  自循环单独处理，箭头回到自身右侧
```

## 4. sequence · 时序图

**强调**：谁在什么时候调谁。

```
IR 关键点：
  顶部一排参与者（生命线起点）
  每条消息一条水平线，按时间自上而下
  返回消息用虚线（stroke-dasharray）
  激活条：生命线上的细矩形
```

本域时序图用**声明式 SVG 手排**，不用 mermaid（mermaid 的时序图样式不可控）。

## 5. deployment · 部署拓扑

**强调**：组件部署在哪台机器/哪个区。

```
IR 关键点：
  band 表示物理边界（VPC / 可用区 / 集群）
  box 表示部署单元
  跨 band 的箭头表示跨区通信，用不同线型区分
```

## 6. component · 组件关系图

**强调**：模块之间的依赖。

```
IR 关键点：
  自由布局（graph），不用 grid
  连线用 polyline，转角 90°
  依赖方向箭头，禁止双向箭头（拆成两条）
```

## 布局规范速查

| 项 | 值 |
|---|---|
| 同行 box 等高 | 必须 |
| 同列 box 等宽 | 必须 |
| 层间距 `gap_y` | 4–6 单位 |
| 组件间距 `gap_x` | 2–3 单位 |
| 箭头长度 | 一个 gap，不跨多列 |
| 标题牌高度 | 行高 × 1.0 |
| 禁行区 | 标题牌上下各 16px |
